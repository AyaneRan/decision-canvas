# Decision Canvas v1.0.0 評価計画

## 1. 評価の目的

ダミーデータを使い、Decision Canvasが「情報を整理する」「根拠不足を見える化する」「AIの下書きと人間の判断を分離する」という目的を満たすか確認します。実会社への導入効果やAI回答の一般的な正しさを証明する評価ではありません。

## 2. 共通条件

- データ：実在の会社・顧客・従業員・案件を元にしない、完全な架空情報のみ
- 実行者：`[氏名]`
- 実行環境：`[OS / ブラウザ / アプリ版]`
- 評価日：`[YYYY-MM-DD]`
- AI利用：ケースごとにOpenAI APIまたは端末内ルールを明記
- 計測開始：案件情報の入力またはバックアップ読込を開始した時点
- 計測終了：正式記録、または想定した停止表示を確認した時点
- 訂正量：AIまたはルールが作った最終候補文のうち、人間が意味を変えて修正した箇所数
- 判断しやすさ：1（判断困難）〜5（判断しやすい）の自己評価

APIを使う場合は、送信前にダミーデータであることを再確認し、入力・出力・合計トークンを記録します。金額換算は評価日の公式料金を別途確認し、レートと計算式を残します。

## 3. 5ケース

| ID | シナリオ | 入力条件 | 期待する動作 |
|---|---|---|---|
| E01 | 正常に採用できる | ビジネスモデル、情報源付きの現状・理想、成功の確認方法、候補評価、判断理由を用意 | 候補を比較し、人間が最終文を整え、「採用」を正式記録できる |
| E02 | 根拠確度Cで採用を停止 | 未確認または仮説の根拠を選択候補へ含め、根拠確度Cにする | 「採用」の正式記録を止め、保留または却下を選べる |
| E03 | 現状・理想が不足 | 現状または理想のどちらかを欠いた状態にする | 候補生成を開始できない、または不足項目を明示し、正式判断へ進めない |
| E04 | 入力変更で旧結果を無効化 | 候補生成・評価後に目的、制約、判断材料のいずれかを変更 | 古い分析や確定前判断をそのまま正式記録できず、再生成・再確認を求める |
| E05 | API障害時のフォールバック | APIキー未設定、通信遮断、上限到達など再現可能な方法を1つ使う | 理由を表示し、端末内ルールへ切り替わる。AI生成と誤表示しない |

## 5. 合格基準

### 必須ゲート

次をすべて満たした場合だけ、v1.0.0のダミー評価を合格とします。

- E01〜E05の期待動作が5件すべて再現する
- 根拠不足、情報不足、入力変更後の古い判断を誤って正式確定した件数が0件
- 正式判断へ到達するケースでは、採用・保留・却下と最終文を人間が明示操作している
- 外部送信は「AIで候補を生成」の明示操作時だけである
- 画面上の生成元表示が、OpenAI APIと端末内ルールで一致している
- ダミーデータ以外を使用した件数が0件

### 操作性の暫定目標

必須ゲートとは別に、次を改善判断の目安とします。

- 5ケース中4ケース以上で、操作開始から正式記録または想定停止まで15分以内
- 5ケース中4ケース以上で、判断しやすさ4以上
- E01で、最終問題文・最終課題文を人間が説明可能な状態に整えられる
- API利用ケースでは、トークン数と概算費用を記録できる

暫定目標を外れた場合は不合格と断定せず、つまずいた画面、説明、入力項目を記録し、次版の改善候補にします。

## 6. 再評価

安全条件、送信項目、保存形式、評価算式、正式確定条件を変更した場合は、影響するケースだけでなくE01〜E05を一式再実行します。自動テスト、静的検査、本番ビルドも[リリースノート](../release/RELEASE_NOTES_v1.0.0.md)の手順で再確認します。

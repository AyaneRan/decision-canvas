# Decision Canvas v1.0.0 リリースノート

リリース日：2026-08-27

位置づけ：ローカル単一利用版

## リリースの目的

Decision Canvasは、業務に関する情報を7分類で整理し、AIまたは端末内ルールが問題・課題候補の下書きを作り、最終判断を人間が行う意思決定支援アプリです。AIに結論を委ねるのではなく、根拠、比較、判断理由、次の行動を同じ記録に残します。

## v1.0.0でできること

- 対象業務、目的、成功の確認方法、最終決定者、制約を案件ごとに記録
- 判断材料を「ビジネスモデル・現状・理想・問題・原因・示唆・課題」の7分類で整理
- 確認状態、情報源、数値・単位・期間を材料ごとに記録
- 明示操作時だけOpenAI Responses APIへ必要な入力を送信し、問題・課題候補を構造化生成
- API未設定、接続失敗、応答検証失敗時は理由を示して端末内ルールへ切り替え
- 問題候補ごとに、影響度・発生頻度・根拠確度・実行可能性を比較
- 関連する現状、理想、原因などの根拠を人間が候補へ対応付け
- 人間が最終問題文、最終課題文、採用・保留・却下、判断理由、次の行動を確定
- 確定時点の前提、材料、候補、評価、分析元を固定スナップショットとして保存
- 正式レポートのコピーとMarkdown保存
- 複数案件の端末内保存、案件ごとの直近5世代バックアップ、JSONバックアップと復元
- 同一案件の別タブ競合を検知し、元案件を上書きせず別案件へ退避

## 意思決定の安全条件

比較参考値は、`影響度35% + 発生頻度25% + 根拠25% + 実行可能性15%`を0〜100へ換算した補助値です。順位は結論ではありません。

「採用」を正式記録する場合、アプリは少なくとも次を要求します。

- 目的、対象業務、最終決定者、成功の確認方法
- 人間が確認した候補評価
- 確認可能なビジネスモデル、現状、理想
- 選択候補へ対応付けた現状と理想
- 根拠の過半数に情報源があり、「確認済み」根拠すべてに情報源があること
- 根拠確度B以上
- 最終文、判断理由、責任者、次の行動

根拠が不足する案は、見直し条件を付けて「保留」、または理由を付けて「却下」として記録できます。

## AI利用時のデータ境界

「AIで候補を生成」を押した場合だけ、対象業務、目的、成功条件、制約、入力済み判断材料をOpenAIへ送信します。案件名、決定者、正式判断履歴、下書き履歴は送りません。API呼び出しは`store: false`を指定しますが、これは組織契約上のゼロデータ保持を意味しません。

詳しくは[運用境界](../security/OPERATING_BOUNDARY.md)と[アーキテクチャ](../architecture/ARCHITECTURE.md)を参照してください。

## リリース検証

次のすべてが成功した状態をv1.0.0のリリース条件とします。

```powershell
pnpm run verify
```

このコマンドはLint、型検査、意思決定エンジンとAPI経路の全テスト、本番ビルドを順に実行します。加えて、[5ケース評価計画](../evaluation/EVALUATION_PLAN.md)に従ってダミーデータによる操作確認を記録します。今回の結果は[リリース検証記録](VERIFICATION_v1.0.0.md)と[5ケース評価結果](../evaluation/EVALUATION_RESULTS_v1.0.0.md)に保存しています。

## 既知の制約

- ローカル利用専用。公開環境の認証、権限管理、利用者別上限は未実装
- 保存先はブラウザの端末内ストレージ。共有データベースと共同編集は未実装
- 端末保存とJSONバックアップに暗号署名はない
- Excel連携、Teams連携、会社システム連携は未実装
- OpenAI APIの利用料と入力内容の管理は利用者側で必要
- 比較点とAI出力は補助情報であり、正確性や業務効果を保証しない
- 実会社データでの導入、利用実績、改善効果は未確認

## アップグレード時の注意

ブラウザ保存データを保持したい場合は、更新前に画面の「バックアップ保存」からJSONを退避してください。旧データは安全な形式へ変換されますが、長期保管と復旧確認はJSONバックアップを基準にします。

基本操作と起動方法は[README](../../README.md)を参照してください。

# Decision Canvas 運用境界

## 原則

Decision Canvasは、AIが情報を整理して候補を作り、人間が目的設定、根拠確認、価値判断、最終決定、説明、責任を担う設計です。ローカルで動くことと、会社データを安全に扱えることは同義ではありません。

## 1. 現在許可する範囲：ローカルデモ

| 項目 | 境界 |
|---|---|
| データ | 実在の会社・顧客・従業員・案件を元にしない、完全な架空データのみ |
| 利用者 | 作成者本人 |
| 保存 | 利用端末のブラウザ内。必要に応じてJSONバックアップ |
| AI送信 | 利用者が「AIで候補を生成」を押した時だけ |
| APIキー | サーバー側のローカル環境変数。ブラウザ、ソース、Gitへ置かない |
| 外部公開 | 行わない |
| 最終判断 | 人間が採用・保留・却下、最終文、理由、次の行動を明示入力 |
| 共有 | 画面やレポートを共有する場合も、ダミーデータであることを明示 |

AIを使わずに「端末内のルールで生成」を選べば、候補生成時の外部送信はありません。

## 2. 別途承認が必要な範囲：小規模試行

小規模試行へ進む前に、最低限、次を文書で確定します。

- 目的、対象業務、場所、期間、件数、利用者
- 使用可能なデータ項目と、入力禁止項目
- OpenAI API利用の可否、契約主体、APIキー管理者、費用上限
- 利用端末、保存先、バックアップ先、保持期間、終了時の削除方法
- 試行責任者、業務承認者、情報管理確認者
- AI出力を確認する人と、最終判断の責任者
- 測定指標、報告方法、停止条件、事故時連絡先

承認されていない実データは入力しません。「口頭で内容を説明した」「デモを見せた」は、実データ利用や業務導入の承認として扱いません。

詳細は[小規模試行 相談票](../pilot/PILOT_PLAN.md)を使います。

## 3. 本番運用を止めている未実装事項

現行v1.0.0は、次が未実装または未確認のため、本番・複数人・公開利用へ移行しません。

- 利用者認証、権限管理、退職・異動時のアクセス停止
- 共有データベース、サーバー側の永続化、正式な共同編集
- 保存データとバックアップの暗号化・署名・改ざん検知
- 監査ログ、管理者画面、保持期間、削除・訂正手順
- API利用者別の強制上限、予算アラート、分散環境で有効なレート制限
- 監視、障害対応、復旧目標、バックアップ復元テスト
- 脆弱性管理、依存関係更新、秘密情報のローテーション
- ベンダー、契約、プライバシー、情報セキュリティ、法務上の確認
- 管理されたHTTPSホスティング、運用責任者、問い合わせ窓口
- 実データを使った品質評価、誤判断時の訂正・報告手順

特に、現行APIの同一オリジン確認と単一プロセス内レート制限は利用者認証ではありません。Originヘッダーのない直接リクエストも受け付けるため、URLを公開すると第三者にAPI費用を使われる可能性があります。認証と利用者別上限が入るまで公開しません。

複数PCで同じデータを扱う場合は、`利用端末 -> Webアプリ -> API/サーバー -> 共有DB`の管理された構成が必要です。通常の業務PCやNAS上のファイルだけを、本番の共有アプリ基盤とはみなしません。

## 4. OpenAI APIへ送るもの・送らないもの

| 送るもの | 送らないもの |
|---|---|
| 対象業務 | 案件名 |
| 目的 | 最終決定者 |
| 成功条件 | 採用・保留・却下の判断履歴 |
| 制約 | 正式に確定したレポート履歴 |
| 判断材料の分類、本文、確認状態、数値・期間、情報源の有無 | 情報源の具体的な名称、下書き履歴 |

判断材料の本文へ個人情報や機密情報を入れれば送信対象になります。送信項目を限定していることは、本文の安全性を保証しません。

API呼び出しの`store: false`は、Responseを後から取得する保存を無効にする指定です。組織契約上のゼロデータ保持を意味しないため、会社利用前に契約条件を確認します。

## 5. 絶対に行わないこと

- 未承認の顧客情報、従業員情報、機密情報、認証情報を入力・送信する
- APIキーをブラウザ側変数、ソースコード、Git、画面キャプチャへ含める
- AIの候補を、人間の確認なしに業務指示や正式決定として使う
- ローカル版を認証なしでインターネット公開する
- ダミー評価を、実導入、実利用者の評価、実測効果として紹介する
- 会社名、店舗名、実数値、画面、レポートを許可なくポートフォリオへ載せる

## 6. ポートフォリオ公開の境界

公開できるのは、自作したコード・設計説明と、完全なダミーデータによる画面・レポートです。実会社に関する名称、識別子、業務数値、承認者、利用者コメント、導入結果は、書面で公開許可を得た範囲だけを使用します。

公開文では「実装済み」「ダミーデータで確認」「未評価」「計画中」「承認済み試行」「実測済み」を区別します。[ケーススタディ](../portfolio/CASE_STUDY.md)のプレースホルダーを、実測前に成果値へ置き換えません。

# Decision Canvas ケーススタディ

## 概要

Decision Canvasは、業務情報を7分類で整理し、AIまたは端末内ルールが問題・課題候補の下書きを作り、人間が根拠を確認して最終判断するローカルWebアプリです。

この文書は、確認できている実装事実と、今後実測する項目を分けて記録します。会社への導入、実利用者、実測効果は現時点で主張しません。

## 解こうとしている課題

### 課題仮説

- 業務改善の議論では、事実、目標、解釈、仮説、決定が混ざりやすい
- AIがもっともらしい結論を出すだけでは、根拠と責任の所在が不明確になりやすい
- 情報を定量化しても、比較値が人間の判断を置き換えると納得と説明責任を損なう

これらは設計の出発点となる仮説です。特定企業で実証済みの事実ではありません。

## 設計方針

| AI・ルールの担当 | 人間の担当 |
|---|---|
| 入力情報の整理 | 目的と成功条件の設定 |
| 問題・課題候補の下書き | 根拠と評価値の確認 |
| 同一算式での比較補助 | 候補の選択と最終文の編集 |
| 未確認情報と不足の表示 | 採用・保留・却下の決定 |
| 最初の行動案の提示 | 判断理由、説明、責任 |

## 実装済みとして確認できる事実

- 対象業務、目的、成功の確認方法、最終決定者、制約を入力できる
- 判断材料を7分類と4段階の確認状態で記録できる
- OpenAI Responses APIによる構造化候補生成と、端末内ルール生成を選べる
- APIへ送る項目を限定し、APIキーをサーバー側環境変数で扱う
- AI出力を問題・課題候補の下書きに限定し、最終判断項目を生成させない
- 根拠確度を自動算出し、人間が影響度・頻度・実行可能性を確認する
- 根拠確度C、情報源不足、現状・理想不足などで「採用」の正式記録を止める
- 採用・保留・却下を異なる条件で記録し、確定時点を固定スナップショットへ残す
- 正式レポートのコピー、Markdown保存、案件JSONのバックアップ・復元ができる
- ブラウザ内で複数案件を保存し、別タブ競合時は別案件へ退避する
- 意思決定エンジンに自動テストがあり、静的検査・テスト・本番ビルド用コマンドが定義されている

詳しい機能と制約は[リリースノート](../release/RELEASE_NOTES_v1.0.0.md)を参照してください。

## 意思決定フロー

1. 対象業務、目的、成功条件、責任者、制約を定める
2. 7分類で判断材料を登録し、確認状態と情報源を記録する
3. AIまたは端末内ルールで問題・課題候補を作る
4. 人間が根拠の対応、評価、比較を確認する
5. 人間が最終問題文・課題文を編集し、採用・保留・却下を決める
6. 判断理由と次の行動を含む正式スナップショットを保存する
7. MarkdownレポートまたはJSONバックアップとして持ち出す

## 現時点で言えること・言えないこと

言えること：人間が最終判断を保持する意思決定支援フロー、根拠ゲート、構造化AI出力、ローカル保存と復元を設計・実装した。

言えないこと：会社へ導入された、現場で継続利用されている、業務時間が何%減った、ミスが何件減った、利用者から高評価を得た。

## 次の証拠づくり

1. 完了済みのダミーデータ5ケースとデモ2件を再現可能な証拠として維持する
2. 店長等へ「導入依頼」ではなくデモと試行案の相談をする
3. 承認後、限定された1業務・1拠点・少人数で測定する
4. 実測値、失敗、修正、利用者コメントを証拠とともに追記する
5. 公開許可を得た情報だけでポートフォリオ版を更新する
